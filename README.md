## Design

This lab implements an IPv4 subnetting and forwarding program with three commands: info, split, and lookup. The library in lab.c handles address and route parsing, CIDR calculations, subnet splitting, and forwarding-table operations.

The CIDR calculations handle /0, /31, and /32 explicitly. A /0 uses a zero mask and covers the entire IPv4 address space. Its host count is calculated using 64-bit arithmetic to represent (2^{32}) addresses, then subtracts the network and broadcast addresses. A /31 has two usable addresses for a point-to-point link. A /32 represents one address, which is both the first and last host.

The forwarding table uses a binary trie for longest-prefix lookup. Each level represents one address bit, from most significant to least significant. Lookup follows the destination’s bits and remembers each matching route; the last match is the most specific. A default /0 route is stored at the root and is used when no more specific route matches.

## Analysis

The program performs the info, split, and lookup commands as expected. Networks are parsed correctly to provide the needed info and networks are split evenly as long as they are positive power of 2 requests. Routing lookups examine the table for longest prefix and are routed correctly. Because the example table has a default route through a gateway, every valid IPv4 address will match some route in the table. This means the program can select a route for the address; it does not guarantee that the gateway or any later router can actually deliver packets to it.
